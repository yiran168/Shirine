# Shirine 全站修复验收记录

本次修改针对动态内容、用户菜单、资源访问与前后台交互。测试在项目内的临时数据库完成，没有用测试账号修改线上数据。

## 修复内容与原因

|问题|原因与处理|
|---|---|
|发布文章正文空白|文章索引不含正文，却被当作可渲染的本地文章；标准文章地址与自定义地址均改为读取真实详情，动态 Markdown 使用对应渲染器。受保护正文不会出现在未解锁的 HTML 中。|
|相册重复解锁、照片数量为 0|浏览器 API 统一走同源 Cookie，页面不缓存用户权限状态；相册数量读取后端实际照片字段。验证重复解锁仅扣款一次。|
|看板娘不显示、按钮不统一|前后台共享控件与四语文案，以真实模型加载事件判断成功，失败可重试；按钮固定在屏幕左下角，后台侧栏留出底部操作空间。|
|加载动画裂图|修复 SVG 内样式文本的 XML 转义。|
|跳转与主题切换等待|去掉页面切换的额外等待、滚动动画与页面缓存；主题颜色计算使用有限缓存。后台入口使用完整导航，避免布局容器不同导致过渡失败。|
|音乐连续跳过、时长为零|保留歌单接口所需的授权参数；失效解析自动尝试备用服务，解析完才设置音源，旧请求不能覆盖新曲目。播放失败明确提示并停止；未知时长显示占位符。|
|后台设置重复|玻璃效果合并为一个全站开关；技能、项目、设备由专门管理模块维护，不再重复列入独立页面。|
|排序与统计|站点罗盘分组和番剧条目增加左上角拖拽手柄；统计模块可出现在友链、动态、番剧、罗盘、相册及更多页面。|
|用户体系|访客、用户、管理员菜单分权；即时切换头像、每日签到、退出登录。管理员不参与积分领取与调整，统计排除管理员积分。|
|外部跳转|更多菜单的 GitHub 地址由系统设置控制。|

## 头像资源

50 位不同番剧角色来自 8 部作品的官方 SNS 头像赠送页面，保留场景与装饰背景；每位提供 384×384 WebP 和 96×96 缩略图。旧文件已删除，已有账号的旧地址由 API 转换为新头像。来源、版权说明及完整链接见 [头像素材来源](avatar-sources.md)。

站长名片、中英文 README 页首、文档站与文章页标识使用站长提供的同一原图。执行 `node scripts/process-furina-avatar.mjs` 可从项目内原图重新导出；无需访问项目外目录。

## 媒体访问与部署

R2 资源通过同源签名地址访问，链接有效期为 10 分钟；受限资源每次读取仍校验登录、购买或密码授权。跨站浏览器请求、伪造签名、未发布及未关联资源会被拒绝，数据库鉴权异常时不读取 R2。长时间打开页面的图片可续签一次。普通账号不能通过任意头像地址公开未发布资源。

部署流程先完成测试、类型检查和体积检查，再发布前后端；两端成功后运行 `scripts/secure-r2.mjs` 关闭并核验目标存储桶的 r2.dev 与自定义域名公共访问。该步骤需要部署令牌拥有相应 R2 管理权限；脚本失败会使部署任务失败。应用代码通过 R2 绑定继续访问资源。最终线上状态必须以相应提交的 Actions 结果为准。

此措施减少公开源地址和盗链风险；合法访客看到的图片仍可被保存，不能承诺完全阻止下载。音乐实际可用性也取决于平台提供的公开音源及地区、会员限制。
